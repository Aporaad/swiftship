# تطوير واختبار Auth محلياً

**النطاق:** PostgreSQL محلي وقاعدة `alx_api_test` فقط، مع حسابات اختبار اصطناعية. لا يقرأ الإعداد `.env` البعيد ولا يتصل بـSupabase.

## تهيئة قاعدة الاختبار وتشغيل suite

تتطلب البيئة PostgreSQL محلياً ووجود قاعدة `alx_api_test`، واتصالاً محلياً بصلاحية إنشاء الأدوار اللازمة داخل قاعدة الاختبار.

```bash
cd alx_api
TEST_DATABASE_URL='postgresql://<local-superuser>@localhost/alx_api_test?host=/var/run/postgresql' npm run test:db
```

تطبيق migrations `0002`–`0006` هنا جزء من الاختبار المحلي. يقوم الاختبار بإعادة إنشاء مخطط API ومستخدميه الاصطناعيين داخل `alx_api_test`، ويختبر RLS والصلاحيات والمعاملات وتسجيل الدخول والترقية الأولى لـArgon2id وتدوير الجلسات وإبطالها وتغيير/استعادة كلمة المرور بعد محاكاة cutover وRBAC. في النهاية يترك مستخدماً اصطناعياً واحداً لتجربة الخادم:

- المعرّف: `legacy-test`
- كلمة المرور الاختبارية القديمة: `Development-password-123`
- PIN اصطناعي مختلف: `local-only-pin-2468` — لا يقبله API بديلاً عن كلمة المرور.

لا تستخدم هذه القيم خارج قاعدة localhost التجريبية.

## إنشاء مفاتيح وإعداد محلي ثم تشغيل الخادم

```bash
npm run setup:local-env
npm run dev:local
```

ينشئ الأمر ملف `.env.development.local` المستثنى من Git وبصلاحية `0600`، مع مفتاحي Ed25519 محليين وhash Argon2id وهمي، ويرفض أي قاعدة ليست loopback واسمها `alx_api_test`، ويرفض استبدال ملف موجود. الأمر `dev:local` يقرأ هذا الملف فقط؛ لا يستخدم `.env` البعيد. يستمع الخادم على `127.0.0.1:3001`، لا على واجهة عامة.

في أول طلب دخول ناجح بكلمة المرور الاصطناعية القديمة، يتحقق PostgreSQL من القيمة داخل دالة مقيدة، ويُنشأ hash Argon2id في المخطط الخاص. بعدها تبقى كلمة المرور القديمة غير مطلوبة من API. لا يستخدم PIN ككلمة مرور. حالة الخادم المحلي عند البدء تترك legacy authentication مفعلاً وعمليات تغيير/استعادة كلمة المرور معطلة حتى cutover صريح.

## حدود التدفقات الحساسة

- تغيير أو إعادة تعيين كلمة المرور معطّل في الإعداد الافتراضي. يتطلبان `LEGACY_PASSWORD_AUTH_ENABLED=false` و`AUTH_PASSWORD_CHANGES_ENABLED=true` معاً حتى لا يختلف سر المستخدم بين API والواجهة القديمة.
- مسار طلب الاستعادة لا يصبح فعّالاً حتى تركيب `PasswordResetDelivery` مع قناة تسليم معتمدة؛ لا يرسل API رابطاً أو token حالياً. تختبر قاعدة الاختبار token بإيصال in-memory مؤقت فقط.
- سياسة كلمات المرور: نقل تدريجي عند أول دخول صحيح إلى Argon2id؛ لا نقل جماعي ولا PIN. المستخدم الذي لا يملك اعتماداً قديماً صالحاً يحتاج reset/invitation عبر قناة موثوقة.
- RBAC deny-by-default بلا wildcard أو role/permission seeds. سبب تأجيل matrix الإنتاج: توجد اختلافات بين bootstrap شاشة الأدوار والصلاحيات الافتراضية في واجهة إدارة المستخدم؛ يلزم توحيد هذه السياسة قبل منح مستخدمي الإنتاج صلاحيات.
- المهاجرتان `0005_auth_core_passwords_and_events.sql` و`0006_rbac_foundation.sql` مخصصتان لهذه الجولة المحلية؛ لا تُطبقان على Supabase أو أي قاعدة مشتركة من دون مراجعة/موافقة منفصلة.
