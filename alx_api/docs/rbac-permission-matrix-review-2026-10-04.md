## قاعدة الدمج المقترحة للمراجعة

اعتُبر الدمج **اتحاداً**: منح كل دور صلاحية إذا كانت ممنوحة في أي من مصدري الدورين، حتى لا تختفي صلاحية افتراضية سابقة بصمت. هذه قاعدة محافظة على التوافق لكنها قد **توسّع الصلاحيات**؛ ليست توصيةً تلقائية بالـseed. لذلك يجب مراجعة الفروق عالية التأثير أدناه قبل اعتمادها.

## فجوة محرر صلاحيات المستخدم

قاموس `PermissionKey` يضم **152** صلاحية صريحة، بينما واجهة تعديل صلاحيات المستخدم تعرض **128** فقط. الـ24 الموجودة في القاموس لكنها لا تظهر في `permissionGroups.ts` هي:

`add_couriers`, `add_customers`, `add_products`, `delete_couriers`, `delete_custody_advances`, `delete_customers`, `delete_paid_orders`, `delete_products`, `edit_cbm_shipping_rate`, `edit_couriers`, `edit_custody_advances`, `edit_customers`, `edit_order_items`, `edit_products`, `edit_profit_per_kg`, `manage_website`, `post_financial_entries`, `return_order_items`, `view_couriers`, `view_custody`, `view_customers`, `view_order_items`, `view_products`, `view_website_management`.

قد تكون بعضها صلاحيات قديمة أو تكرارات دلالية (مثال: `view_custody` و`view_custody_advances`)، لكن لم تُدمج أو تُحذف تلقائياً. يلزم قرار: إضافتها لمحرر الواجهة، تعليمها legacy، أو اعتماد aliases بعد اختبار الاستخدام.

## قيود أمان لا تتغير في المقترح

- لا ينقل API قائمة `ROOT_EMAILS` الصلبة أو auto-promote إلى Admin الموجودة في `useRole.ts`; في API تكون الصلاحية ناتجة عن إسناد `user_roles` صريح.
- يظل RBAC deny-by-default؛ ممنوع wildcard `*` في grants الفعلية.
- يوصى بدور واحد فعّال للمستخدم في أول نشر حتى تُراجع دلالة جمع صلاحيات أدوار متعددة.
- لا seed لأي دور أو permission قبل اعتماد الأعداد والاختلافات الخطرة أعلاه، ولا تطبيق migration `0005/0006` على Supabase قبل عرضها وموافقة منفصلة.

## المطلوب للمراجعة

1. هل تقبل أن يبقى **Admin** بدور شامل مع 152 permission صريحة، أم ينبغي تقسيمه إلى صلاحيات أضيق؟
2. هل توافق على 41 إضافة لمحاسب بما فيها صلاحيات حذف/ترحيل/عكس، أم نأخذ bootstrap الـ16 فقط لبعض هذه الأكواد؟
3. هل نُبقي إضافات Employee الست و`track_order` لـCourier؟
4. كيف تُعالج صلاحيات القاموس الـ24 الغائبة عن محرر الواجهة؟

**لا تغييرات DB أو seeds نُفذت لإنشاء هذا التقرير.**
