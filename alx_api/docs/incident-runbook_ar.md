# دليل التشغيل والحوادث — SwiftShip API

## مؤشرات المراقبة

- معدل `5xx` و`4xx` حسب المسار والصلاحية.
- زمن `p50/p95/p99` للمصادقة والطلبات والمالية.
- فشل readiness أو ارتفاع أخطاء Pool.
- فشل Refresh/Re-use Detection ومحاولات login الفاشلة.
- عدد عمليات fallback من API إلى Legacy.
- تأخر Outbox وإعادة المحاولة وفشل المزود الخارجي.
- اختلاف عدادات ومجاميع البيانات بين API والمصدر الانتقالي.

## الاستجابة الأولية

1. ثبت `requestId` ووقت الحادث والمسار والنسخة دون تسجيل Tokens أو كلمات مرور.
2. افحص `/api/v1/health/live` و`/api/v1/health/ready`.
3. راجع structured logs ومعرف الإصدار.
4. أوقف feature flag المتأثر إلى fallback إذا كان ذلك آمنًا.
5. لا تنفذ SQL تصحيحيًا مباشرًا على بيانات مالية دون migration أو إجراء موثق.

## حوادث المصادقة

عند الاشتباه في تسريب جلسة: أوقف الجلسة أو جميع جلسات المستخدم، أعد تعيين كلمة المرور من مسار Admin المحمي، راجع `auth_events`، ولا تطلب من المستخدم إرسال كلمة المرور في قناة الدعم.

## حوادث البيانات والمالية

أوقف الكتابات المتأثرة، احفظ نسخة من السجلات والـrequest IDs، قارن الأرصدة والمجاميع، استخدم reversal للقيود بدل الحذف، وفعّل rollback فقط بعد قرار مسؤول الإصدار.

## إغلاق الحادث

يجب توثيق السبب الجذري، نطاق التأثير، الخط الزمني، الإجراء التصحيحي، اختبار منع التكرار، وقرار إعادة تفعيل العلم.
