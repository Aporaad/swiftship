

## تحديث متابعة 2026-10-03 — عزل حدود Supabase

### ما أُغلق برمجياً

- تم إنشاء `src/data/legacy/legacy-adapter.ts` كنقطة توافق وحيدة للمحول القديم داخل النظام.
- تم نقل استيرادات المحول القديمة من صفحات ومكونات وخدمات النظام إلى نقطة التوافق المركزية.
- أضيف `legacy-boundary.test.ts` لمنع عودة الاستيراد المباشر من `src/lib/supabase` خارج الحد.
- في `Aporaad/alx_web` تم إنشاء `src/api/legacy-portal.ts` ونقل استيرادات Supabase من الصفحات والسياق والمكونات والتخطيطات إليه.
- أضيف `npm run audit:portal-boundary` للموقع، ونتيجته: `Portal boundary clean`.
- بُني النظام والموقع بنجاح بعد التغيير.
- الالتزامات المرفوعة: النظام `ebfe2a2`، والموقع `bffae17`.

### الحالة الحالية للبوابات

| البوابة | الحالة |
|---|---|
| حدود الاستيراد المباشر في النظام | مغلقة برمجياً؛ الاستيراد المباشر محصور في نقطة التوافق |
| حدود الاستيراد المباشر في الموقع | مغلقة على مستوى الصفحات/السياق/المكونات؛ التنفيذ القديم ما زال داخل حد Portal مؤقت |
| Gateway registry للنطاقات السبعة عشر | موجود ومختبر wiring |
| Auth boundary في النظام | موجود، مع بقاء جسور توافق legacy لبعض المستهلكين |
| AsyncState | موجود ومختبر ومطبق على دفعات؛ يلزم تدقيق Query/Mutation شامل قبل إغلاق المرحلة 12 نهائياً |
| RLS/grants/جودة البيانات | غير قابل للتحقق في هذه الجولة؛ موصل Supabase غير مفعّل |
| alx_web HTTP Portal endpoints | غير قابل للتحقق حيّاً قبل نشر Endpoint خادمي وربطه ببيئة staging |

### قرار الجاهزية

لا يُعلن **اكتمال التجهيز الإنتاجي الكامل لإنشاء API** ما دام snapshot قاعدة البيانات وRLS/grants وجودة البيانات غير منفذ، وما دام Portal Gateway يعمل بتنفيذ توافق legacy بدلاً من HTTP endpoint خادمي متحقق حيّاً. أما حدود الكود والاستيرادات والبناء فهي مثبتة ومرفوعة إلى GitHub، ويمكن متابعة إغلاق AsyncState وtyped legacy في دفعات لاحقة دون تغيير قاعدة البيانات.
