# Phase 5 — فصل المصادقة الحالية تمهيداً لـ Auth API

**الحالة:** مكتملة ضمن نطاق الفصل والتجهيز؛ لم يُبنَ نظام Auth جديد أو API مصادقة.
**التاريخ:** 2026-09-28

## القرار المعتمد

- لا تُستعاد هوية المستخدم من كائن محفوظ في `localStorage` أو `sessionStorage`؛ بعد تحديث الصفحة تُعامل الحالة على أنها غير مصادق عليها ويُطلب تسجيل الدخول.
- عند توفير Gateway موثوق يعيد جلسة قابلة للتحقق والتجديد، يستعيد `AuthSessionProvider` الجلسة ولا يطلب الدخول مجدداً إلا عند انتهاء المصادقة أو إبطالها.
- يبقى تحقق بيانات الدخول الحالي مؤقتاً خلف `AuthGateway` التوافقي؛ هذه المرحلة لا تستبدل مصدر المصادقة الحالي ولا تنشئ API جديداً.

## التنفيذ

- إضافة `CurrentUserDto` خالٍ من حقول كلمة المرور ورمز `systemPin`، و`SessionState` بحالات `loading` و`authenticated` و`unauthenticated` و`expired` و`locked`.
- إضافة عمليات الجلسة إلى عقد `AuthGateway`: التحقق من بيانات الدخول، إكمال الدخول بعد تحقق الحساب ورمز PIN، قراءة/مراقبة الجلسة، الإلغاء، التحديث، والخروج.
- إنشاء `AuthSessionProvider` مستقل يتعامل مع `AuthGateway` فقط، وتركيبه حول `App` في `main.tsx`.
- تحويل `CurrentSupabaseAuthGateway` إلى حد توافق مع Adapter الحالي. الجلسة الحالية داخل الذاكرة فقط؛ `getCurrentSession()` لا يثق بكائن مستخدم محفوظ بعد إعادة التحميل.
- إزالة استعادة المستخدم المحفوظ ومسح مفتاحه القديم عند التهيئة والخروج. لا تُنشأ الجلسة إلا بعد التحقق من الحساب وحالة التعطيل/الدور، وبعد إدخال PIN عند الحاجة.
- نقل استهلاك الجلسة في `App` و`useRole` و`FinanceAccounting` والخدمات ذات الصلة إلى الـProvider/Gateway. توجد واجهة `legacyAuth` مؤقتة داخل الـProvider لتحويل DTO إلى شكل `uid` القديم؛ لا تستورد الواجهة `auth.currentUser` مباشرة من Adapter.
- أبقيت PIN المستخدم في حالة React مؤقتة أثناء شاشة التحقق فقط؛ لا يدخل في DTO أو Storage.

## الجلسات المستقرة مستقبلاً

يدعم `AuthSessionProvider.refresh()` و`signOut()` عبر `AuthGateway`. عندما يُضاف Auth API، يجب أن ينفذ Gateway استعادة/تجديد الجلسة والتحقق منها ثم يصدر `SessionState`; لا يغيّر الـProvider أو الصفحات. التنفيذ التوافقي الحالي **لا يحفظ refresh token**، لذلك يتطلب تسجيل دخول جديد بعد إعادة تحميل الصفحة حسب القرار المعتمد.

- `npm run check -- --pretty false` — ناجح.
- `npm test -- src --reporter=dot` — 26 ملف اختبار ناجح.

- عند تشغيل كل مجموعة الاختبارات، نجحت 145 حالة وتجاوزت 3، وتعثر اختبار تكاملي واحد يتطلب الوصول الخارجي إلى Supabase بـ`ConnectTimeoutError`؛ اختبارات `src` المحلية نجحت.
- لم تُجرَ أي تغييرات على مخطط قاعدة البيانات أو بياناتها.
- `npm run build` — ناجح للواجهة وخادم الإنتاج. ظهرت تحذيرات Vite غير حاجبة حول `import.meta` في إخراج CJS وحجم بعض chunks؛ لم تمنع إنتاج ملفات البناء.
