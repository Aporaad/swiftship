# المرحلة 8 — تقرير التحقق من قاعدة البيانات دون تغيير — 2026-10-02

## نطاق التنفيذ

هذا التقرير قراءة وتحليل للملفات الموجودة في المستودع فقط. لم يتم فتح اتصال قاعدة بيانات ولم يتم تنفيذ SQL أو DDL أو DML في هذه الدفعة.

## 1. صحة المخطط من المصدر المرجعي

- وثيقة `DATABASE_SCHEMA.md` تسجل **51 جدولاً** في المخطط المرجعي.
- المجالات الرئيسية الظاهرة: المستخدمون والجلسات، الطلبات والشحنات، الحسابات والقيود، الأدوار والصلاحيات، التذاكر، المواقع الجغرافية، التسويات، وسجلات التدقيق.
- مفاتيح IDs موثقة كـ `uuid` أو `bigint` أو `text` حسب الجدول، مع علاقات مرجعية ظاهرة داخل تعريفات الحقول.
- المفاتيح الأجنبية الموثقة تشمل علاقات إلى `users`, `accounts`, `orders`, `status`, `city`, `country` وغيرها.
- حقول JSONB المؤكدة من الوثيقة: `audit_logs.old_data`, `audit_logs.new_data`, `auto_entries.data`, و`roles.permissions`، إضافة إلى حقول `data` موثقة في جداول أخرى.
- الأعمدة المالية الظاهرة تشمل `balance`, `percentage`, `fixed_amount`, مبالغ الطلبات والتسويات، وأعمدة تفاصيل القيود.
- حقول حساسة أو عالية الحساسية تحتاج تحققاً حياً: كلمات المرور، system PIN، tokens، مفاتيح الجلسات، وعناوين IP.
- التقرير المرجعي لا يكفي وحده لإثبات حالة RLS الحالية أو العلاقات الفعلية إلى `auth.users`; يجب تنفيذ استعلامات القراءة المحدودة عبر connector قاعدة البيانات في جلسة تالية.

## 2. جودة البيانات — Backlog قراءة فقط

| الفحص | الحالة من الملفات | الأولوية |
|---|---|---|
| Orders بلا Customer | غير قابل للإثبات من الملفات | High |
| Orders بلا Tracking Number | غير قابل للإثبات من الملفات | High |
| Shipments بلا Order | غير قابل للإثبات من الملفات | High |
| Users بلا Role صالح | غير قابل للإثبات من الملفات | Blocker |
| Users تحتوي Password أو System PIN | حقول حساسة موجودة في مسارات legacy ويجب فحصها | Blocker |
| Sessions قديمة أو غير مربوطة | جدول `user_sessions` موثق، لكن لا توجد counts حية | High |
| Foreign Keys غير متطابقة | العلاقات موثقة جزئياً فقط | High |
| Status خارج القيم المعتمدة | يحتاج استعلاماً حياً | Medium |
| مبالغ سالبة | يحتاج فحصاً حسب المجال | High |
| Epoch مقابل timestamptz | migrations السابقة توثق توحيد audit timestamps؛ يلزم فحص الباقي | Medium |
| تكرار البريد أو اسم المستخدم | يحتاج استعلاماً حياً | High |

## 3. تقرير الوصول

- واجهة العميل تحتوي حالياً على legacy Supabase boundary في `alx_web`، مع بدء نقل `AnnouncementsPage` إلى `PortalGateway`.
- HTTP Portal Gateway معطل افتراضياً خلف `VITE_PORTAL_API_ENABLED` حتى نشر endpoints والتحقق من المصادقة.
- لا يجب اعتبار مفاتيح الواجهة العامة بديلاً عن authorization؛ يجب أن تكون endpoints خادمية وتتحقق من الجلسة والملكية والصلاحية.
- لا يتم اعتماد الإغلاق النهائي لهذه المرحلة قبل الحصول على snapshot حي لـRLS والـgrants وارتباط الجداول بـ`auth.users`.

## 4. القيود والقرار

- لا يمكن استنتاج عدد الصفوف أو حالة RLS أو grants أو foreign-key violations من المستودع وحده.
- لا يتم إصلاح أي نتيجة في هذه المرحلة؛ النتائج تتحول إلى backlog مصنف كما في الجدول أعلاه.
- الخطوة التالية: تفعيل أداة/connector قراءة قاعدة البيانات، تنفيذ استعلامات metadata وquality مقسمة ومحدودة، حفظ النتائج، ثم مراجعة readiness قبل أي API server split.
