# إغلاق P6 — الدفعة الثانية

**التاريخ والوقت:** 2026-10-20 06:05 (+03:00)  
**النموذج المنفذ:** Manus  
**الحالة:** P6 مغلقة برمجيًا

## التنفيذ

اكتملت عقود ومسارات تفاصيل المسابقة العامة للبوابة، مع حصر النتائج بالمسابقات المنشورة أو النشطة. أضيف تسجيل المشاركة من خلال جلسة البوابة فقط، ويستخرج الخادم `portalUserId` و`linkedCustomerId` من ملف الحساب ولا يقبل أي هوية أو معرف عميل من جسم الطلب. كما يفرض العقد قبول الشروط صراحةً.

تم تفعيل منع المشاركة المكررة عبر القيد الفريد الموجود على `(contest_id, customer_id)` ومعالجة تعارض القيد كاستجابة تجارية `409`، مع تسجيل حدث التدقيق.

تمت إضافة قائمة الإدارة للمشاركات، ومراجعة المشاركة إلى `eligible` أو `ineligible` أو `disqualified` مع سبب إلزامي وفاعل مسجل، إضافة إلى audit event.

تمت إضافة تجميد snapshot للمؤهلين بعد إغلاق المسابقة. تنشئ العملية `feature_draw_runs` بحالة `ready`، وتحسب عدد المؤهلين وبصمة SHA-256 حتمية لقائمة `entry_id/customer_id` المرتبة. العملية idempotent بواسطة `idempotencyKey` ولا تنفذ أي اختيار عشوائي.

تم تحديث عقود TypeScript وZod وOpenAPI لمسارات الإدارة والبوابة، وإضافة اختبارات مخططات القبول والمراجعة وsnapshot.

## التحقق

نجح `tsc --noEmit`، ونجحت اختبارات P6 وعددها 9/9، ونجحت مجموعة `alx_api` الكاملة سابقًا بعد الدفعة الأولى وعددها 52 suite و458 اختبارًا، كما نجح Prettier و`git diff --check`.

لم تنفذ هذه الجولة SQL أو DDL فعليًا على قاعدة البيانات، ولذلك لم يتم تعديل `DBdevloping_history.md` أو `db_commends.md`. أوامر SQL الموجودة داخل repository لا تنفذ إلا عند استدعاء المسارات في بيئة تشغيل متصلة بقاعدة البيانات.

## حدود ما بعد P6

تظل القرعة العشوائية، اختيار الفائز، تخصيص الجوائز للفائزين، إصدار الكوبونات، وتكامل كوبون العميل مع تسعير الطلب مراحل لاحقة من الخطة وليست جزءًا من إغلاق P6.
